4. 사용 유형

감독형(디렉터형) + 분업형

아이디어와 자료(PDF, 딥리서치 보고서, 캡처)를 주고 Claude가 끝까지 만들게 한다. 그다음 직접 써 보며 다듬는다. 조사·구현·문서를 서로 다른 AI에 맡긴다.

  • 시작: 한 줄 아이디어 + 자료 → "질문하면서 계획 세워"
  • 제작 중: "링크 줘", "서버 줘"로 직접 써 보기 → 피드백
  • 마무리: 점검 요청 → "커밋하고 푸시" → Streamlit 배포 → README
  • 고정 스택: Python + Streamlit. 평일 낮(수업 시간) 사용이 대부분이다

5. 강점

아이디어를 배포까지 끝내는 실행력 위임

근거: 하루에 카지노 게임 6개를 만들어 각각 커밋·푸시한 날이 있다. 커밋 1,296개, 새 저장소 45개 이상

대부분의 입문자는 만들다 멈춘다. 배포와 README까지 끝내는 습관이 이미 있다.

사용자 눈으로 결함을 잡는 판정 감각 분별

근거: "3번 4번 답 같음", "원본이랑 같아?", IQ 문항 규칙 오류 지적, EQ "당연한 정답 문항" 지적

직접 풀어 보고 설계 결함까지 찾는다. AI가 놓치는 부분을 사람이 잡는 역할을 제대로 한다.

실패를 규칙으로 바꾸는 능력 설명

근거: 파일럿에서 나온 오류 11유형을 '마스터 규칙'으로 만들어 나머지 720문항에 적용. EQ '착한 답 금지' 규칙

잘 쓰는 사람들의 핵심 행동이다. 같은 실수가 반복되지 않게 하는 장치를 스스로 만든다.

도구를 목적별로 나눠 쓰는 분업 위임

근거: 조사는 Gemini 딥리서치, 기획은 ChatGPT, 구현은 Claude Code, 문서는 Claude AI로 나눈다(에이전트 리포트, 각 AI 보고서)

AX 컨설턴트가 고객에게 제안해야 할 "업무별 도구 배치"를 이미 스스로 하고 있다.

AI가 먼저 질문하게 함 설명

근거: 8월 초 "객관식으로 질문하면서 확인해" 이후 "질문하면서 계획 세워"가 습관이 됨. 계획 먼저 요청은 7월 3.3%에서 10월 8.0%로 늘었다

Anthropic이 권하는 '인터뷰 → 설계서 → 실행' 방식과 같다.

비용·경계 감각 책임

근거: 무료·저가 모델 선택, "호출 비용 아까워 내가 돌릴게". 카지노는 가상 칩만, 팀 저장소는 요청할 때만, 팀원 이름 가리기

신뢰가 자산인 기술영업·AX 직무에 그대로 이어지는 습관이다.

6. 약점

끝난 기준 없이 맡김 설명

근거: 끝난 기준을 붙인 요청은 전체의 6.0%이고, 14개월 내내 한 번도 9%를 넘지 않았다. 검증은 "테스트 5회", "100번 실행"처럼 횟수로 요구한다

횟수는 기준이 아니다. "선택지 4개가 모두 달라야 한다" 같은 통과 조건이 있어야 AI가 스스로 걸러 낼 수 있다. 가장 효과가 큰 단일 개선점이다.

'됐다'를 증거 없이 믿음 분별

근거: 증거 요구 7.5%. 다시 고치라는 요청 113회, 불신 표현 35회, "다 확인했다며" 반복

AI가 "확인했다"고 말하는 것과 실제로 확인한 것은 다르다. 증거를 받으면 검토가 빨라지고 재요청이 줄어든다.

이해 없이 통째로 위임 위임

근거: 에러 원문만 붙여넣은 메시지 223회(대부분 Claude Code 밖). 이유를 묻는 메시지는 7월 16.7%에서 10월 10.3%로 줄었다

Anthropic 실험에서 코드를 통째로 맡긴 그룹은 이해도 퀴즈 점수가 40%에 못 미쳤다(7장). 내가 읽지 못하는 코드는 내가 검증할 수도 없다.

한 대화를 너무 오래 씀 위임

근거: 메시지 50개가 넘는 대화 11개, 3일 넘게 이어진 대화 26개. 사용량 한도 7회

대화가 길어질수록 AI는 앞의 지시를 잊고 실수가 늘어난다. "내 요청을 무시했다"는 느낌의 원인 중 하나다.

조사 → 구현 인계와 출처 검증이 약함 책임

근거: ChatGPT 자기 보고서가 "조사 요청과 실제 조사 완료를 구분하는 기준이 약하고, 다른 AI로 넘긴 기록이 없다"고 지적. 딥리서치 결과를 교차 검증하지 않은 채 구현에 씀

분업은 잘하지만 이음매가 비어 있다. 조사 결과가 틀리면 그 위에 만든 것도 다시 해야 한다.

넓게 벌리고 깊게 마무리하지 못함 · 겉 지표 책임

근거: 약 35개 중 깊이 있는 것은 퀴즈·IQ·EQ·팀 챗봇 정도. 10월 초에 잔디 색과 커밋 날짜를 맞추는 데 하루 대부분을 씀

포트폴리오를 보는 사람은 개수보다 대표작 3개의 깊이와 기록의 신뢰를 본다.

8. 보완점 — 바로 복사해서 쓰는 문장

① 통과 조건 먼저

지금: "오류 없을 때까지 테스트 5회"

"끝난 기준: ① 선택지 4개가 모두 다르다 ② 원본에 그림이 있으면 문제에도 있다 ③ 정답을 고르면 정답 처리된다. 전체를 이 기준으로 검사하는 스크립트를 만들고 결과 표를 보여줘."

② 말 대신 증거

지금: "오류 없는 거 맞지?"

"통과한 테스트 출력과 화면 캡처 3장을 같이 보여줘. 확인 못 한 건 확인 못 했다고 따로 적어줘."

③ 조사 → 구현 인계 메모

지금: Gemini 딥리서치 결과를 통째로 붙여넣고 "이걸로 만들어줘"

(Gemini에게) "이 조사를 구현 담당 AI에게 넘길 인계 메모로 정리해줘: 확인된 사실(출처 URL) / 추정 / 결정할 것 / 만들 것 / 끝난 기준."

④ 한 대화 = 한 주제

지금: 한 대화에서 앱 여러 개를 며칠씩 진행

"여기까지 인계 메모 써줘(한 일·남은 일·결정 사항)." → 새 대화에 붙여넣고 시작. 같은 수정이 2번 실패하면 새 대화에서 더 자세히 요청한다.

⑤ 만든 뒤 '왜' 3개

지금: 결과물만 받고 다음 요청

"이 코드에서 가장 중요한 3줄과 그 이유를 설명해줘. 그다음 내가 이해했는지 퀴즈 3개 내줘."

⑥ 검사는 다른 눈에게

지금: 만든 Claude가 스스로 점검

다 만든 뒤 새 대화에서 "이 앱의 버그를 찾는 검사관 역할을 해줘. 끝난 기준 목록과 비교해서 통과/실패 표로."

⑦ 잔디 대신 대표작 3개

지금: 커밋 날짜·색 맞추기

대표작 3개(EQ 테스트, LangChain 챗봇, 이 회고 에이전트)의 README 맨 위에 데모 링크 · 한 줄 요약 · 검증 수치를 넣는다.

10. 나라는 사람 (진단이 아니라 관찰)

기술

  • 코드를 직접 쓰는 힘은 초급이지만, 모르는 것을 숨기지 않고 묻는다
  • 측정·평가 감각이 뛰어나다 (문항 중복, 회차 분리, 솔직성 확인 문항)
  • Python·Streamlit·Git·LangChain·ADK·MCP·RunPod를 짧은 기간에 모두 만져 봤다. 넓이는 넓고 깊이는 이제 쌓는 중이다

일하는 방식

  • 완성본을 보면서 고치는 타입이다
  • 기준이 높다: "한 문제도 이런 오류가 없게"
  • 숫자로 말한다: 환수율, 과락 기준, 초 단위 시간
  • 도구를 목적별로 나누는 분업 설계를 한다

배우는 방식

  • 자격증처럼 목표가 분명한 학습을 좋아하고, 공부 도구를 직접 만든다
  • 해 보면서 배우고, 스스로 비유를 만들어 확인한다
  • 부트캠프 이후 학습이 체계화됐다

사회적 면

  • 친구를 위한 것을 만든다 (온라인 흡연장, 데이트 신청서)
  • 팀에서는 경계를 존중한다: 다른 팀원 파일은 건드리지 않고, 이름을 가리고, 합의안을 쓴다
  • AI에게는 직설적이다. 답답하면 감정이 그대로 나온다

동기와 진로

  • 보이는 결과와 인정을 중시한다. 좋은 동력이지만 겉 지표로 흐르면 신뢰를 잃는다
  • 희망 직무인 기술영업·AX 컨설턴트의 흐름(측정 → 보여 주기 → 설득)과 잘 맞는다. 이 회고 에이전트 자체가 "고객의 AI 활용을 진단하는 도구"의 시제품이다
  • 채워야 할 것은 "왜 이렇게 만들었는지"를 설명하는 기술 설명력이다

12. 이 기준선의 한계와 버린 것

  • 지표는 키워드 규칙으로 센 값이다. 절대값보다 다음 달과 비교한 방향을 보는 용도다.
  • 2025-09 ~ 2026-03은 메시지가 57개뿐이라 비율을 해석하지 않았다. 에이전트의 "변화" 표(초반 0.0% → 최근 6.3%)는 이 작은 표본 때문에 생긴 착시라서 쓰지 않았다.
  • 에이전트 리포트의 연구 수치(예: "20% 시간 절약")와 연계 추천은 웹 출처가 0개여서 버렸다. 7장은 다시 확인한 공개 자료로 새로 썼다.
  • 월별 대표 질문 중 건강·생활 같은 개인적인 질문은 이 문서에 넣지 않았다.
  • '나라는 사람'은 성격 진단이 아니라 AI 앞에서 보인 행동의 관찰이다. 강사·팀원의 의견으로 교차 확인하길 권한다.
