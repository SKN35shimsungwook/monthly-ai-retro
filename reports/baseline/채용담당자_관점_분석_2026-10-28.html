채용담당자 관점 포트폴리오·AI 활용 분석

> 작성 기준일: 2026년 10월 28일 > 공개용 보고서: 개인 대화 원문과 비공개 저장소 이름은 싣지 않고, 비공개 활동은 집계치로만 표시했다.

한눈에 보는 평가

현재 포트폴리오에서 가장 선명한 강점은 사용자 문제를 AI·Python 도구로 빠르게 시제품화하고, 문서와 배포까지 연결하는 실행력이다. 기록상 학습 퀴즈, 일정 관리, 업무 자동화, AI 사용 회고 등 실사용 목적을 가진 결과물을 꾸준히 만들었다.

채용 관점에서는 AX 컨설팅, AI 자동화, 기술영업·솔루션 엔지니어처럼 문제를 듣고 작동하는 예시와 설명을 함께 내놓는 역할과 잘 맞는다. 반면 전문 ML 연구자나 깊은 백엔드 엔지니어로서의 숙련도는 현재 포트폴리오만으로 충분히 입증되지 않는다. 여러 프로젝트 중 대표작 몇 개에서 본인이 내린 판단, 구현한 부분, 품질을 확인한 근거를 더 분명하게 보여줄 필요가 있다.

한 줄 소개: 사용자의 반복 업무와 학습 불편을 Python·Streamlit·LLM으로 시제품화하고, 검증과 설명 자료까지 연결하는 AX·AI 자동화형 인재.

1. 조사 범위

  • GitHub에서 확인한 저장소: 60개(공개 40개, 비공개 20개). 기본 브랜치는 모두 main이고, README는 55개에서 확인됐다.
  • 로컬 GitHub 활동 백업: 2026년 7월 7일~10월 17일 커밋 기록 1,296건, 활동일 85일. 공개 저장소 기록 676건, 비공개 저장소 기록 620건.
  • 공통 사용 기록 비교 기간: 2026년 7월 27일~10월 16일. ChatGPT 사용자 메시지 191개, Claude Code 1,209개, Claude 웹 325개.
  • 사용 기록은 내보내기와 로컬 백업에 포함된 범위만 다뤘다. 계정의 현재 사용량이나 GitHub 프로필 설정을 직접 측정한 값은 아니다.

2. 채용담당자 관점의 강점

강점관찰 근거채용 관점
문제를 작동하는 결과물로 바꿈학습 퀴즈, 일정 도구, 자동화 앱, 회고 도구 등 사용 목적이 있는 프로젝트가 여럿 있다.아이디어 제안에 그치지 않고 시연 가능한 결과를 만들 수 있다.
사용자 관점의 검수문제 중복·정답 오류, 앱 동작, 결과 일관성을 반복해서 확인했다.실제 사용자 경험과 결과 신뢰도를 신경 쓴다.
설명과 문서화README, 보고서, 발표 자료와 사용 안내를 꾸준히 만든다.기술 결과를 비전문가에게 전달하는 직무에 강점이다.
빠른 학습과 도구 활용Python, Streamlit, SQL, RAG, LangChain·LangGraph 등 여러 도구를 실습과 결과물에 연결했다.새로운 기술을 짧은 시간 안에 업무 시제품에 적용할 수 있다.
AI 도구를 역할별로 사용ChatGPT는 질문·설계 검토, Claude Code는 구현 반복에 더 많이 쓰는 패턴이 보인다.도구를 분업해 실행 속도를 높이는 편이다.

3. 보완이 필요한 점

  • 대표작과 실험작의 구분: 저장소가 60개라 처음 보는 사람은 어디에 집중해야 할지 판단하기 어렵다. 프로필에는 대표작 3개를 고정하고 나머지는 학습 실험·팀 프로젝트·개인 앱으로 묶는 편이 좋다.
  • 기술 깊이의 증명: AI가 도운 범위와 본인이 결정·구현·검증한 범위를 프로젝트마다 구체적으로 나눠야 한다. 면접에서는 설계 선택과 실패 원인을 본인 말로 설명할 수 있어야 한다.
  • 완료 기준과 근거를 초반에 제시: Claude Code 기록을 분석한 기존 키워드 지표에서는 완료 조건을 붙인 요청이 약 5.1%, 증거를 요구한 요청이 약 6.9%였다. 키워드 기반 추정치라 참고용이지만, 조건을 먼저 정하면 재작업을 줄일 수 있다는 신호다.
  • 커밋 수를 작업량과 동일시하지 않기: 활동 기록에는 한 시각에 여러 파일을 추가한 묶음 커밋이 보인다. 예를 들어 9월 24일 기록의 64건은 파일 묶음 추가 작업으로 나타난다. 커밋 수는 독립적인 개발 작업이나 완성도를 뜻하지 않으므로 결과물과 검증 근거를 함께 제시해야 한다.
  • 포크와 팀 작업을 명확히 표시: orca는 stablyai/orca의 포크다. 팀 저장소도 원본과 본인 기여를 구분해 표기해야 한다.

4. GitHub 잔디와 저장소 해석

백업된 활동 데이터에는 비공개 저장소 커밋이 620건, 공개 저장소 커밋이 676건으로 기록돼 있다. 이는 저장된 커밋 이벤트의 합계이며, 실제 프로필 기여 그래프 숫자와 같다고 단정할 수 없다. GitHub 잔디에는 커밋 이메일, 기본 브랜치, 저장소가 포크인지 여부 등이 영향을 준다. 비공개 기여 공개를 켜면 외부에는 기여 수만 익명으로 보이고 저장소 세부 내용은 표시되지 않는다. GitHub 기여 기준, 비공개 기여 공개 설정

비공개 저장소의 개별 이름과 원문은 공개 문서에 포함하지 않았다. 비공개 활동은 합계만 표시한다.

기록상 주된 용도디버깅 설명, RAG·아키텍처 질문, API 설정, 조사·문서웹은 학습·코드 도움, Code는 구현·수정·배포

ChatGPT는 짧은 질문으로 설명이나 설계 점검을 받는 조언자에 가깝다. Claude 웹은 학습과 오류 해결에, Claude Code는 프로젝트 기능을 구현하고 다듬는 데 더 많이 사용됐다. 공통 기간 기준으로 Claude 사용자 메시지는 ChatGPT보다 약 8배 많다.

월별 메시지 수는 ChatGPT가 7월 2개, 8월 35개, 9월 68개, 10월 86개였다. Claude는 두 제품을 합쳐 각각 199개, 423개, 333개, 579개였다. 10월은 16일까지의 기록이다. 사용 방식이 설명·학습 중심에서 Claude Code 기반 구현 중심으로 이동한 흐름이 보인다.

6. 작업 성향과 직무 적합성

기록상 사용자는 배우면서 직접 만들어 보는 실험형·제품형 작업자다. 자격증 공부나 반복 업무처럼 구체적인 불편에서 출발해 앱을 만들고, 사용해 보며 오류를 찾는다. 실행력과 사용자 관점, 기술 결과를 설명 자료로 바꾸는 힘이 두드러진다.

현재 증거와 잘 맞는 직무는 AX·AI 자동화 컨설팅, 솔루션 엔지니어, 기술영업, 고객 문제를 빠르게 시제품으로 검증하는 AI 제품 역할이다. ML 연구나 플랫폼 백엔드 직무를 목표로 한다면 모델 평가, 자료구조·시스템 설계, 배포 운영 등 해당 분야의 깊이를 별도 프로젝트로 입증해야 한다.

7. 포트폴리오 우선순위

1. monthly-ai-retro: 여러 AI 서비스와 GitHub 기록을 모아 근거 기반 회고를 만드는 개인 프로젝트다. 데이터 수집, SQLite, RAG, 근거 검증, 민감정보 처리의 흐름을 한 화면에서 보여주면 차별성이 크다. 2. langchain-migration-assistant: 팀 프로젝트다. 이전 버전 코드를 새 버전에 맞게 바꾸고 근거와 검증을 붙이는 문제 해결 흐름이 분명하다. 본인 담당 기능과 팀 성과를 나눠 작성해야 한다. 3. license: 자격증 학습용 퀴즈 앱이다. 문항 정확도, 문제은행 규모, 사용성 개선, 배포 결과를 수치와 화면으로 보여주는 것이 좋다.

각 README 첫 화면에 문제, 대상 사용자, 데모, 본인 역할, 구조, 테스트 결과, 한계와 다음 계획을 넣는다. 프로젝트 이름과 저장소 수보다 세 대표작의 품질 근거를 우선해서 보여준다.

8. 다음 보완 단계

1. 대표작 3개를 GitHub 프로필에 고정하고, 포크·팀 프로젝트의 기여 범위를 표시한다. 2. 프로젝트별로 완료 조건과 검증 결과를 README에 추가한다. 예: “문항 정답 검증 500개 통과”, “주요 화면 모바일 점검 완료”. 3. 면접 답변을 문제 → 결정 → 구현 → 검증 → 배운 점 순서로 준비한다. 4. AI 코드 사용 후 핵심 구조를 본인이 설명하고, 테스트 실패 원인을 직접 추적하는 연습을 한다. 5. 잔디 그래프는 작업 이력의 결과로 두고, 날짜나 이력을 꾸미기보다 재현 가능한 결과물과 사용자 효과를 내세운다.
