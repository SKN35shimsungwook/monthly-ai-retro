# 월간 AI 활용 회고 에이전트 (monthly-ai-retro)

Claude Code · Claude AI(웹·앱) · ChatGPT · Gemini 사용 기록과 GitHub 활동을 한 곳(로컬 DB)에 모으고,
**LLM + RAG 에이전트(LangGraph)가 AI 컨설턴트로서** 종합 리포트 · 타임라인 · 질문 답변 · 연계 추천을 만들어 주는 회고 도구입니다.
나는 읽으면서 👍/👎와 다음 목표만 고릅니다.

> **첫 결과물: [AI 활용 기준선 리포트 (PDF)](reports/baseline/AI활용_기준선리포트_2026-10-18.pdf)**
> 처음 기록(2025-09)부터 2026-10-18까지 AI 4곳 메시지 2,701개 · 커밋 1,296개를 분석한 0회차 기준선입니다. 이후 월간 리포트는 이 숫자와 비교됩니다.

## 1. 무엇을 하나

| 메뉴 (작업 순서) | 내용 |
| --- | --- |
| **1 만들기** | 0 사용 실태(서비스별 용도·빈도) → 1 AI 보고서 받기(서비스마다 맞춤 프롬프트) → 2 자동 가져오기(내보내기 파일·Claude Code·GitHub) → 3 리포트 만들기 |
| **2 리포트** | 요약 · 월별 흐름 · 사용 유형 · AI를 잘 쓰는 사람들의 특징 · 강점·약점(4D, 근거 원문) · 보완점(복사용 문장) · 변화 · 나라는 사람 · 연계 추천 · 지표 · 목표 |
| **3 타임라인** | 서비스별 월별 사용량, 지표 추이, 리포트 카드 |
| **4 묻기** | 내 기록에서 찾아(RAG) 근거 ID와 함께 답하는 컨설턴트 채팅 |
| 도움말 | 흐름도, 처음 한 번 / 매달 할 일 |

## 2. 작동 원리

```
[이 PC 안]                                              [LLM 호출]
내보내기 파일·Claude Code 로그·GitHub
   → importers (서비스별 파서, 민감정보 가리기)
   → SQLite DB (data/db/history.db)
   → TF-IDF 검색 색인 (RAG)
섹션 6개마다 (LangGraph)
   근거 검색 ──────────────────────────────▶ 컨설턴트 작성 (ChatGPT / Gemini)
   근거 검증 ◀──────────────────────────────┘
     (없는 근거 ID? 통계에 없는 %? 민감정보?) → 실패하면 이유를 붙여 다시 쓰기 (최대 2번)
연계 추천 · 'AI 잘 쓰는 사람' 조사 ──────────▶ 웹 검색 + 작성 → 출처 [S번호] 검증
월별 흐름 · 요약 ───────────────────────────▶ 작성
   → reports/<라벨>.analysis.json (단계마다 중간 저장)
```

- **근거 기반**: 모든 관찰에 `[C-123]` 같은 기록 ID를 붙여야 통과합니다. 리포트 화면에서 근거 원문을 바로 펼쳐 볼 수 있습니다.
- **한도 대응**: 429(분당 한도)가 나면 안내된 시간만큼 기다렸다가 자동으로 다시 시도합니다. 하루 한도나 크레딧 부족이면 바로 멈추고 이유를 알려 줍니다.
- **이어 하기**: 단계가 끝날 때마다 `reports/<라벨>.partial.json`에 저장합니다. 중간에 멈추면 다시 눌렀을 때 남은 단계부터 이어서 만듭니다.
- **모델**: 보내는 양이 큰 초기 총정리는 ChatGPT API(gpt-4.1-mini)가 기본이고, 월간 리포트는 무료 Gemini(flash)가 기본입니다.
- **출처 없는 내용 막기**: 웹 검색 출처가 0개면 한 번 더 검색합니다. 그래도 없으면 해당 섹션을 지어내지 않고 비워 둡니다.

## 3. 실행

```bash
pip install -r requirements.txt
python -m streamlit run streamlit_app.py
```

키는 앱의 '만들기 → 3 리포트 만들기'에서 넣습니다. `.streamlit/secrets.toml`에 `GEMINI_API_KEY`, `OPENAI_API_KEY`로 저장되며 커밋되지 않습니다.

```bash
python -m pytest -q   # 47개
```

## 6. 개발 히스토리

Claude Code와 대화하며 만든 과정을 순서대로 정리했습니다. 각 단계에서 무엇을 요청했고, 무엇이 문제였고, 어떻게 바꿨는지를 적었습니다.

### ① 출발점: 한 번짜리 사용 분석 보고서 (2026-10-16)
- 요청: "내 Claude 사용 유형과 방식을 분석하고, AI를 잘 쓰는 사람들의 특징을 조사해서 강점·약점·보완점, 그리고 나라는 사람을 분석해 줘."
- Claude Code가 Claude Code 기록(1,182개 메시지)을 전부 읽고 보고서를 썼습니다. 이것이 `0-initial.analysis.json`입니다.
- 진단 틀: Anthropic AI Fluency 4D(위임·설명·분별·책임), BCG 현장 실험, Anthropic 코딩 실력 연구.

### ② 매달 하는 회고 프로그램으로 (v1)
- 요청: "블로그 자동화처럼 매달 사용 방식과 개선점을 스스로 파악하는 프로그램."
- 결정: AI 요약 초안 + 내가 수정, 지표 4묶음(15개), 나만 사용, 수집기 + 리포트.
- 만든 것: 수집기(`collector/collect.py`), 민감정보 가리기, 리포트·타임라인 앱, Claude 스킬 `monthly-ai-report`.

### ③ "사용 기록일 뿐, 시험 같다" → 보고서형으로 다시 (v2)
- 피드백: "질문이 시험처럼 되어 있고 가시성이 너무 안 좋다. 처음 보고서처럼 분석·추천·장단점이 나와야 한다. 내가 최대한 많이 쓰지 않게."
- 변경: 목차와 섹션 이동, 강점·약점 카드, 👍/👎 한 번 누르기, 목표 고르기(자동 저장), 복사 버튼이 있는 추천 문장.

### ④ LangChain 챗봇처럼: DB + LLM + RAG 종합 에이전트 (v3)
- 요청: "챗봇 만들 때 DB를 만들고 LLM + RAG로 했잖아. Claude·ChatGPT·Gemini 기록을 똑같이 받아서 보고서·타임라인을 만드는 종합 AI 에이전트."
- 만든 것
  - SQLite DB, 서비스별 파서, TF-IDF 검색
  - LangGraph 섹션 그래프(검색 → 컨설턴트 작성 → 근거 검증 → 재시도)와 '묻기' 그래프
  - Gemini 프롬프트를 '15년 차 AX 컨설턴트'로 섹션별로 다시 씀
- 연계 추천 추가: 약점과 이미 쓰는 도구를 보고 새 기술·플러그인·스킬을 웹에서 찾아 추천하며, 출처 [S번호]가 필수입니다.

### ⑤ 서비스마다 다른 프롬프트, 그리고 '처음부터 지금까지' (v4)
- 피드백: "Claude·ChatGPT·Gemini 프롬프트가 같은 게 말이 되냐." → 먼저 **사용 실태**(서비스별 용도·빈도)를 묻고, 그에 맞춰 서비스별 '내 사용 보고서' 프롬프트를 만들도록 바꿨습니다.
  - ChatGPT: 이미지 생성·딥리서치·기획 상담
  - Gemini: 딥리서치·이미지·영상·빠른 질문
  - Claude AI: 아티팩트 시제품·문서
- 피드백: "언제부터 썼는지 정하지 말고 처음부터 현재까지." → 시작 연도 설정을 없애고, 초기 총정리는 모든 기록을 기준선으로 삼게 했습니다.
- 피드백: "만들기 → 리포트 → 타임라인 → 묻기 순서로. 사이드 탭은 불편하다." → 위쪽 메뉴를 작업 순서대로 두고 사이드바를 없앴습니다.

### ⑥ 기록 전부 가져오기
- **Gemini**: AI에게 물으면 "기록 없음"이라고 답해서 Google 테이크아웃을 쓰기로 했습니다. 한국어 `내활동.html` 파서를 새로 만들었고, 2025-09부터 664개를 가져왔습니다.
- **Claude AI**: 처음 올린 내보내기 파일은 manifest뿐이었습니다. 파일 3개(대화·메모리·프로젝트)를 내려받는 방식을 추가해 634개를 가져왔습니다.
- **Claude Code와 Claude AI 구분**: 둘을 다른 서비스로 표시하게 했습니다. Claude Code는 이 PC의 개발 에이전트이고, Claude AI는 웹·앱 대화입니다.
- **ChatGPT**: 내보내기 zip에서 이미지 첨부·생성 메시지도 포함하게 했습니다.
- **GitHub**: gh CLI로 커밋 1,296개를 가져왔습니다(포크 제외).

### ⑦ 첫 실행 실패: 429 RESOURCE_EXHAUSTED (2026-10-18)
- 원인: 초기 총정리는 섹션마다 근거 약 70개(약 2만 자)를 보내고, 6개 섹션 + 재시도 + 웹 검색이 1~2분 안에 몰렸습니다. 그래서 Gemini 무료 한도를 넘었습니다. 한도에 걸렸을 때 기다리는 기능도, 중간 저장도 없어서 결과가 모두 사라졌습니다.
- 결정과 변경
  - 호출 간격을 두고, 429가 나면 기다렸다가 자동으로 재시도합니다.
  - 섹션별로 중간 저장하고 이어서 만들게 했습니다.
  - 초기 총정리만 ChatGPT API를 쓰고, 보내는 양은 줄이지 않았습니다(월간은 양이 적기 때문).

### ⑧ 기준선 확정
- 에이전트 리포트(gpt-4o-mini)를 실제로 생성했습니다. 서비스 간 분업과 월별 흐름은 잘 잡았지만 문장이 일반적이었습니다. 웹 검색 출처가 0개여서 연구 수치와 추천은 모델이 지어낸 내용이었습니다.
- Claude Code가 두 리포트를 검토해 통합 PDF를 만들었습니다. 숫자는 전체 통계, 해석은 0회차의 깊이로 쓰고, 연구 부분은 공개 자료로 다시 확인했습니다.
- 웹 검색 출처 0개 문제를 고쳤습니다.
  - 검색을 반드시 실행하게 했습니다.
  - 출처를 읽는 위치를 넓혔습니다.
  - 0개면 한 번 더 검색하고, 그래도 없으면 비워 둡니다.

### 배운 점
- **LLM 결과는 검증 장치가 있어야 믿을 수 있습니다.** 근거 ID 검사 덕분에 섹션 본문은 기록에 묶여 있었습니다. 검사가 약했던 웹 검색 부분에서는 그럴듯한 가짜 수치가 나왔습니다.
- **한 번에 많이 보내는 작업은 실패를 전제로 설계해야 합니다.** 중간 저장과 자동 재시도가 없으면 무료 한도 하나에 모든 결과를 잃습니다.
- **AI에게 '자기 기억'을 묻는 것은 한계가 있습니다.** 몇 년 치 기록은 내보내기 파일이 정답이고, AI의 자기 보고서는 보조 자료로만 씁니다.
