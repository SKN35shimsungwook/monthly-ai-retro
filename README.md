# 월간 AI 활용 회고 에이전트 (monthly-ai-retro)

Claude Code, Claude AI, ChatGPT, Gemini를 매일 쓰면서, 제가 AI를 잘 쓰고 있는지 감으로만 판단하고 있다는 걸 알게 됐습니다.
그래서 네 곳의 대화 기록과 GitHub 활동을 한 곳(로컬 DB)에 모았습니다. 그리고 **LLM + RAG 에이전트(LangGraph)가 AI 컨설턴트처럼** 근거를 붙여 리포트·타임라인·질문 답변·연계 추천을 만들게 했습니다.
저는 리포트를 읽으면서 👍/👎와 다음 목표만 고르면 되도록 만들었습니다.

> **첫 결과물: [AI 활용 기준선 리포트 (PDF)](reports/baseline/AI활용_기준선리포트_2026-10-18.pdf)**
> 처음 기록(2025-09)부터 2026-10-18까지, AI 4곳에 보낸 제 메시지 2,701개와 커밋 1,296개를 분석한 0회차 기준선입니다. 앞으로 매달 이 숫자와 비교하려고 합니다.

## 1. 무엇을 하나

| 메뉴 (작업 순서) | 내용 |
| --- | --- |
| **1 만들기** | 0 사용 실태(서비스별 용도·빈도) → 1 AI 보고서 받기(서비스마다 맞춤 프롬프트) → 2 자동 가져오기(내보내기 파일·Claude Code·GitHub) → 3 리포트 만들기 |
| **2 리포트** | 요약 · 월별 흐름 · 사용 유형 · AI를 잘 쓰는 사람들의 특징 · 강점·약점(4D, 근거 원문) · 보완점(복사용 문장) · 변화 · 나라는 사람 · 연계 추천 · 지표 · 목표 |
| **3 타임라인** | 서비스별 월별 사용량, 지표 추이, 리포트 카드 |
| **4 묻기** | 내 기록에서 찾아(RAG) 근거 ID와 함께 답하는 컨설턴트 채팅 |
| 도움말 | 흐름도, 처음 한 번 / 매달 할 일 |

## 2. 작동 원리

```
[이 PC 안]                                              [LLM 호출]
내보내기 파일·Claude Code 로그·GitHub
   → importers (서비스별 파서, 민감정보 가리기)
   → SQLite DB (data/db/history.db)
   → TF-IDF 검색 색인 (RAG)
섹션 6개마다 (LangGraph)
   근거 검색 ──────────────────────────────▶ 컨설턴트 작성 (ChatGPT / Gemini)
   근거 검증 ◀──────────────────────────────┘
     (없는 근거 ID? 통계에 없는 %? 민감정보?) → 실패하면 이유를 붙여 다시 쓰기 (최대 2번)
연계 추천 · 'AI 잘 쓰는 사람' 조사 ──────────▶ 웹 검색 + 작성 → 출처 [S번호] 검증
월별 흐름 · 요약 ───────────────────────────▶ 작성
   → reports/<라벨>.analysis.json (단계마다 중간 저장)
```

- **근거 기반**: 모든 관찰에 `[C-123]` 같은 기록 ID를 붙여야 통과합니다. 리포트 화면에서 근거 원문을 바로 펼쳐 볼 수 있습니다.
- **한도 대응**: 429(분당 한도)가 나면 안내된 시간만큼 기다렸다가 자동으로 다시 시도합니다. 하루 한도나 크레딧 부족이면 바로 멈추고 이유를 알려 줍니다.
- **이어 하기**: 단계가 끝날 때마다 `reports/<라벨>.partial.json`에 저장합니다. 중간에 멈추면 다시 눌렀을 때 남은 단계부터 이어서 만듭니다.
- **모델**: 보내는 양이 큰 초기 총정리는 ChatGPT API(gpt-4.1-mini)가 기본이고, 월간 리포트는 무료 Gemini(flash)가 기본입니다.
- **출처 없는 내용 막기**: 웹 검색 출처가 0개면 한 번 더 검색합니다. 그래도 없으면 해당 섹션을 지어내지 않고 비워 둡니다.

## 3. 실행

```bash
pip install -r requirements.txt
python -m streamlit run streamlit_app.py
```

키는 앱의 '만들기 → 3 리포트 만들기'에서 넣습니다. `.streamlit/secrets.toml`에 `GEMINI_API_KEY`, `OPENAI_API_KEY`로 저장되며 커밋되지 않습니다.

```bash
python -m pytest -q   # 47개
```

## 6. 만든 과정 (회고)

Claude Code와 대화하면서 만들었습니다. 단계마다 제가 무엇을 원했고, 어디서 막혔고, 어떻게 바꿨는지 적어 둡니다.

### ① 출발: 한 번짜리 사용 분석 보고서 (2026-10-16)
처음에는 "내 Claude 사용 방식을 분석하고, AI를 잘 쓰는 사람들과 비교해서 강점·약점·보완점, 그리고 나라는 사람을 분석해 달라"고만 요청했습니다.
Claude Code가 제 메시지 1,182개를 전부 읽고 쓴 보고서가 `0-initial.analysis.json`입니다.
생각보다 정확해서 한 번으로 끝내기 아까웠습니다. 이게 출발점이 됐습니다.

### ② 매달 하는 회고 프로그램으로 (v1)
블로그 자동화처럼 매달 제 사용 방식과 개선점을 스스로 파악하는 프로그램을 만들고 싶었습니다.
AI가 초안을 쓰고 제가 고치는 방식으로 정했습니다. 지표는 4묶음 15개로 정하고, 수집기·민감정보 가리기·리포트 앱을 만들었습니다.

### ③ "사용 기록일 뿐, 시험 같다" → 보고서형으로 다시 (v2)
직접 써 보니 질문이 시험지처럼 느껴지고 한눈에 들어오지 않았습니다. 처음 받은 보고서처럼 분석과 추천이 나와야 했습니다.
그래서 화면을 다시 짰습니다.
- 목차로 섹션을 이동하게 했습니다.
- 강점·약점을 카드로 보여 주게 했습니다.
- 👍/👎는 한 번 누르면 끝나게 했습니다.
- 추천 문장에는 복사 버튼을 달았습니다.

제가 직접 써야 하는 건 최소로 줄였습니다.

### ④ LangChain 챗봇처럼: DB + LLM + RAG 에이전트 (v3)
수업에서 LangChain 챗봇을 만들 때 쓴 'DB에 넣고 LLM + RAG로 답하기' 구조를 그대로 가져왔습니다.
- SQLite DB, 서비스별 파서, TF-IDF 검색을 만들었습니다.
- LangGraph로 '검색 → 컨설턴트 작성 → 근거 검증 → 재시도' 그래프를 짰습니다.
- 프롬프트는 '15년 차 AX 컨설턴트' 역할로 섹션마다 다시 썼습니다.
- 약점과 지금 쓰는 도구를 보고 새 기술·플러그인을 웹에서 찾아 주는 **연계 추천**도 넣었습니다.

### ⑤ 서비스마다 다른 프롬프트, 그리고 '처음부터 지금까지' (v4)
만들고 보니 Claude·ChatGPT·Gemini에 같은 프롬프트를 쓰고 있었는데, 그건 말이 안 됐습니다. 저는 서비스마다 쓰는 용도가 다르기 때문입니다.
- ChatGPT: 이미지 생성, 딥리서치, 기획 상담
- Gemini: 딥리서치, 이미지·영상, 빠른 질문
- Claude AI: 시제품, 문서

그래서 먼저 사용 실태를 고르게 하고, 그에 맞춰 서비스별 프롬프트를 만들게 바꿨습니다.

나머지 두 가지도 바꿨습니다.
- 언제부터 썼는지는 정하지 않고, **처음부터 지금까지 전부**를 기준선으로 삼았습니다.
- 메뉴는 제가 실제로 일하는 순서(만들기 → 리포트 → 타임라인 → 묻기)로 다시 배치했습니다.

### ⑥ 기록 전부 가져오기
- **Gemini**: AI에게 물어보니 "기록 없음"이라는 답만 돌아왔습니다. 그래서 Google 테이크아웃을 받아 한국어 `내활동.html` 파서를 새로 만들었고, 2025-09부터의 기록 664개를 가져왔습니다.
- **Claude AI**: 처음 받은 내보내기 파일에는 목록(manifest)만 들어 있었습니다. 대화·메모리·프로젝트 파일 3개를 따로 내려받아 634개를 가져왔습니다.
- **Claude Code와 Claude AI는 구분해서 보여 주기로 했습니다.** 하나는 제 PC의 개발 에이전트이고, 하나는 웹·앱 대화라서 쓰임이 다르기 때문입니다.
- ChatGPT는 이미지 메시지까지 넣었고, GitHub에서는 커밋 1,296개를 가져왔습니다.

### ⑦ 첫 실행 실패: 429 RESOURCE_EXHAUSTED (2026-10-18)
초기 총정리를 처음 돌렸을 때 Gemini 무료 한도에 걸렸습니다. 섹션 6개를 다 써 놓고도 결과를 전부 날렸습니다.
원인은 두 가지였습니다.
- 섹션마다 근거 70개(약 2만 자)를 1~2분 안에 몰아서 보냈습니다.
- 한도에 걸렸을 때 기다리는 기능도, 중간 저장도 없었습니다.

그래서 이렇게 바꿨습니다.
- 호출 사이에 간격을 두고, 429가 나면 기다렸다가 다시 하게 했습니다.
- 섹션마다 중간 저장하고, 멈춘 곳부터 이어서 만들게 했습니다.
- 양이 많은 초기 총정리만 ChatGPT API를 쓰기로 했습니다.

### ⑧ 기준선 확정
에이전트 리포트(gpt-4o-mini)는 서비스 간 분업과 월별 흐름은 잘 잡았지만, 문장이 일반적이었습니다. 웹 검색 출처가 0개였는데도 "20% 시간 절약" 같은 숫자를 만들어 넣었습니다.
그래서 두 리포트를 Claude Code와 같이 검토해 하나로 합쳤습니다.
- 숫자는 전체 통계를 썼습니다.
- 해석은 0회차 보고서의 깊이를 살렸습니다.
- 연구 부분은 공개 자료로 다시 확인했습니다.

마지막으로, 웹 검색 출처가 0개면 다시 검색하고 그래도 없으면 비워 두게 고쳤습니다.

### 배운 점
- **LLM 결과는 검증 장치가 있어야 믿을 수 있었습니다.** 근거 ID를 검사한 섹션은 기록에 단단히 묶여 있었습니다. 검사가 약했던 웹 검색 부분에서는 그럴듯한 가짜 숫자가 나왔습니다.
- **한 번에 많이 보내는 작업은 실패를 전제로 설계해야 했습니다.** 중간 저장과 자동 재시도가 없으면 무료 한도 하나에 모든 결과를 잃습니다.
- **AI의 '자기 기억'에는 한계가 있었습니다.** 몇 년 치 기록은 내보내기 파일이 정답이었고, AI가 쓴 자기 보고서는 보조 자료로만 쓰게 됐습니다.
- **제 숫자를 보고 나서야 고칠 점이 분명해졌습니다.** 끝난 기준을 붙인 요청이 6%, 증거를 요구한 요청이 7.5%였습니다. 다음 달에는 이 두 숫자를 올리는 게 목표입니다.
